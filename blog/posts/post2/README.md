# Blog 2: Growth, Job Openings, and Entry Barriers

This post uses O*NET OnLine to compare Bright Outlook occupation titles across Job Zones, then adds concrete occupations and national median wages to turn the comparison into a career-screening strategy. The analysis uses R and rvest only.

## Files
| Location | Contents |
| --- | --- |
| `index.qmd` | Article, inline results, occupation/wage table and original author/date metadata. |
| `code/analyze.R` | Snapshot analysis, rvest wage parsing, figure generation and an optional public-page refresh function. |
| `data/` | `job_zones.csv` and `bright_outlook.csv`, preserving the original scraped tables; `_profiles/` holds four saved public HTML wage profiles. |
| `results/` | Joined occupation data, overlap summary, wage examples (three CSVs) and the chart `outlook_by_zone.png`. These are generated by the analysis. |

## Reproduce
Install dependencies once:

```r
install.packages(c("rvest", "dplyr", "stringr", "ggplot2", "knitr"))
```

Open `index.qmd` and render in Quarto. It sources `code/analyze.R`, reads the supplied snapshots, regenerates tables and the figure, and inserts the calculated values into the article. This default workflow makes no web requests. Alternatively, from the `post2` folder run:

```r
source("code/analyze.R")
result <- analyze_blog2()
```

To demonstrate/repeat collection from the current public website, run the optional function once:

```r
scrape_current_sources()
```

It uses rvest to read the two occupation tables and four example profiles, requests each page once with a one-second pause, and saves into `data/_refresh/`. It never overwrites the original snapshots automatically. Current O*NET lists can differ from the original article; do not mix updated counts with old prose or dates. The underscore-prefixed HTML folders are supporting data, not standalone blog posts.

This preserves the analysis underlying the submitted article rather than substituting the changed live list. This distinction is documented in the article.

## Cleaning and interpretation
The tables are joined by the full O*NET occupation code after checking code uniqueness. The display badge “Bright Outlook” and excess whitespace are removed from occupation names. Of 346 Bright Outlook titles in the preserved snapshot, 15 lack a Job Zone match, leaving 331. The 32 matched titles with both flags are distributed as follows: Zones 1–2: 11; Zone 3: 4; Zone 4: 15; Zone 5: 2. The four illustrative occupations are verified to carry both flags in this snapshot. The graph's “only” labels refer to the growth/openings flags; a new/emerging designation can also apply.

Wages and years are extracted with rvest from each saved profile's “Median wages” entry and annual amount. They are national medians, not local or entry wages. Job Zones combine education, experience and training rather than guarantee eligibility. Counts weight titles equally and are not counts of jobs, vacancies or independent labor markets. Missing matches, broad statistical categories, revisions, local demand, licensing, work authorization and occupation-specific conditions limit recommendations.
